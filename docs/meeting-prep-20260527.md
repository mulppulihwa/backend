## Slide 1 — 우리가 풀려는 문제

**"귀향·귀농민이 본인에게 맞는 정책을 몰라서 놓친다"**

- 정책은 중앙부처·광역·기초자치단체로 분산 → 한 곳에서 확인 불가
- 행정 리터러시 격차 — 특히 디지털 접근이 어려운 고령층
- "알고 보니 신청할 수 있었는데 기간이 지났다"는 후회 반복

**대상 지역:** 충청북도 옥천군 청산면  
**1차 타겟:** 60세 이상 귀향·귀농민  
**2차 타겟:** 귀농 준비자, 귀향민, 귀농 초기 정착자, 공무원·지원 담당자

## Slide 2 — 솔루션

**프로필 5개 질문 입력 → 본인이 받을 수 있는 정책 즉시 추천**

```
비로그인 홈
  → 카카오 로그인
  → 첫 방문: 프로필 입력 (나이·지역·직업·가구·농업여부)
  → 로그인 홈: 맞춤 정책 리스트 (마감 임박순)
  → 재방문: 저장된 프로필 자동 복원
```

**핵심 차별점**
- 챗봇/검색 없이 간단한 폼으로 즉시 결과
- 노인 접근성 최우선 설계 (폰트 18px+, 버튼 52px+)
- 복지로 API 연동으로 정책 데이터 자동 동기화

## Slide 3 — 기술 스택

| 레이어 | 스택 | 비고 |
|---|---|---|
| 백엔드 | Django (Python) + DRF | JWT 인증, 복지로 API 연동 |

| 외부 API | 복지로 API, 카카오 로그인·지도 | |

**아키텍처 흐름**
```
[Next.js 프론트]
      ↕ REST API (JWT)
[Django 백엔드]
      ↕               ↕
[PostgreSQL]    [복지로 API]
                   (정책 데이터 sync)
```

## Slide 5 — 복지로 API 연동 구조

**왜 직접 크롤링 대신 복지로 API를 쓰는가**
- 보건복지부 공식 API → 데이터 신뢰성, 법적 리스크 없음
- 정책 추가·변경 시 관리 커맨드 1번으로 자동 반영

**동기화 흐름**
```
python manage.py sync_welfare_policies
  → 복지로 API 호출 (지역 코드 기준 필터)
  → 정책 파싱 → DB upsert
  → 조건 필드 정규화 (나이·가구·지역 등)
```

**정책 매칭 로직**
- 사용자 프로필 조건 → condition_tree (AND/OR/NOT/LEAF) 평가
- 지역 계층 구조 — 옥천군 사용자는 충청북도 광역 정책도 매칭

### Q2. Web Push 구현 방향 검토 (v2.2.0)

```
브라우저 → POST /api/notifications/subscribe/  (구독 정보 저장)

  → send_d7_alerts 커맨드
```
