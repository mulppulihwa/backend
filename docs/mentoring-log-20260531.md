# 멘토링 일지

**일자:** 2026-05-31

---

## 1. 멘토링 주제

백엔드 성능 최적화, 프론트엔드 UX 개선, 개인 기술 역량 강화

---

## 2. 내용

사회적 농업 복지 서비스(SocialVenture) 개발 현황을 공유하고, 실무 관점에서의 기술적 개선점과 성장 방향에 대해 피드백을 받았다.

주요 논의 사항:
- 정책 매칭 API의 DB 조회 성능 및 캐싱 전략
- User/Policy 데이터 증가 시 스키마 및 인덱스 설계
- UserPolicy 저장 플로우의 성능·오류 처리
- 준비물(체크리스트) 기능 구현 방향
- 프론트엔드 사용자 동선 및 UI 일관성

---

## 3. 멘토 피드백 및 조언

**백엔드**
- 정책 매칭 시 캐싱 전략을 검토할 것 — 현재 매칭 요청마다 DB를 전량 조회하는 구조라면 User/Policy 수가 늘어날 때 병목이 됨. 쿼리 횟수 측정부터 시작할 것
- 스키마와 인덱스를 데이터 증가를 염두에 두고 재검토할 것 (복합 인덱스, GIN 인덱스 등)
- UserPolicy 저장 응답이 1초 가량 걸리는 문제 — 원인 파악 후 쿼리 최적화 또는 비동기 처리 검토
- UserPolicy 중간 이탈 시나리오 처리 — 정책 저장 도중 실패했을 때 상태가 어떻게 남는지 명확히 처리할 것
- UserPolicy 목록 정렬 순서를 명시적으로 정의할 것
- 중복 데이터 insert 방지 로직 검토 (upsert 또는 unique constraint 활용)
- 준비물(체크리스트) 기능은 의미 있는 기능이니 잘 완성할 것

**개인 역량**
- Claude에게 면접 질문을 던지는 방식으로 기술 면접 준비를 꾸준히 할 것
- 요청이 컴퓨터의 어떤 계층(네트워크, OS, 프레임워크)을 거쳐 처리되는지 흐름을 이해할 것
- 정확도가 떨어지는 구간이 어디인지 측정 지표를 두고 원인을 분석할 것
- 프레임워크(Django) 동작 특성을 더 깊게 이해하면 설계 판단이 빨라짐

**프론트엔드**
- 출생년도 선택 UI: 최근 연도가 위로 오도록 정렬하고, 날짜 입력은 date 타입으로 처리할 것
- 홈에서 이미 프로필이 있는 유저에게 재진단을 유도하는 동선은 비효율적 — 바로 결과로 연결하는 흐름 고려
- 닉네임 미설정 시 "00님의 어쩌구" 같은 fallback 텍스트 처리 필요
- 홈 화면 플로팅 버튼이 어색하고 하단 바 뒤로 콘텐츠가 비쳐 보이는 레이아웃 문제 수정 필요
- CTA 문구 "진단하기 시작" → "진단 시작"으로 간결하게
- 새 정책이 추가됐을 때 팝업으로 재진단을 유도하는 UX 고려

---

## 4. 느낀점 및 향후 계획

기능 구현에 집중하다 보니 성능이나 예외 처리 같은 프로덕션 관점의 고민이 부족했다는 걸 느꼈다. 특히 UserPolicy 1초 지연 문제처럼 이미 인지하고 있던 문제를 미루지 않고 측정부터 해봐야겠다.

**향후 계획**
- [ ] UserPolicy 저장 API 응답 시간 측정 및 원인 파악
- [ ] 정책 매칭 쿼리 횟수 로깅 → 캐싱 도입 검토
- [ ] UserPolicy 중간 이탈/중복 insert 예외 처리 보강
- [ ] 프론트 출생년도 UI, 하단 바 레이아웃 버그 수정
- [ ] Claude 면접 질문 풀이 주 1회 이상 실천
