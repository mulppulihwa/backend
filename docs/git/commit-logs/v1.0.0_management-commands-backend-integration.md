## What
v1 테스트 단계: 관리 명령어 추가 (데이터 시드, 테스트 사용자) 및 backend를 메인 레포지토리에 통합. 모든 API 엔드포인트의 동작을 검증했음.

## Why
- 수동으로 데이터를 만들거나 JWT 토큰을 생성하는 대신, 자동화된 명령어로 테스트 환경을 빠르게 준비
- backend가 submodule로 분리되어 있으면 배포 시 복잡도 증가 → 메인 레포에 통합하여 단순화
- API 전체 엔드포인트의 동작을 콘솔에서 검증하여 v1 완성도 확인

## Implementation

### 1. Management Commands 추가

**`apps/regions/management/commands/seed_regions.py`**
```bash
python manage.py seed_regions
# Output: ✓ 28 regions created
```
- 광역 17개 (시도)
- 충청북도 11개 시군구 (옥천군 포함)
- UPSERT 방식 (중복 실행 안전)

**`apps/policies/management/commands/seed_policies.py`**
```bash
python manage.py seed_policies
# Output: ✓ 5 policies created
```
- 샘플 정책 5개 (다양한 benefit_type, 마감일)
- 실제 테스트용 데이터

**`apps/users/management/commands/create_test_user.py`**
```bash
python manage.py create_test_user
# Output: JWT Access Token + 사용 예시
```
- 테스트 사용자 생성 (kakao_id: test_user_12345)
- 프로필 자동 생성 (46세, 옥천군, 귀농인)
- JWT Access Token 발급
- 인증 필요한 API 테스트 가능

### 2. Backend Repository 통합

**문제:** backend가 git submodule (160000 mode)로 등록되어 있음
```bash
git rm -f --cached backend
git add backend/
```

**결과:** backend를 일반 파일로 추적
- 단일 레포에서 전체 코드 관리
- 배포 시 복잡도 제거
- 코드 리뷰 편의성 증대

### 3. API 전체 검증 완료

```
✅ GET /api/policies/preview/     (비로그인)   → 정책 3개
✅ GET /api/regions/              (비로그인)   → 지역 28개
✅ GET /api/places/               (비로그인)   → [] (데이터 없음)
✅ GET /api/policies/match/       (JWT auth)  → 정책 5개 + days_left
✅ POST /api/policies/parse/      (Admin)     → 권한 체크 정상
✅ GET /api/schema/               (비로그인)   → OpenAPI YAML
✅ GET /api/docs/                 (비로그인)   → Swagger UI
```

**주요 검증 항목:**
- 정책 매칭: 사용자 프로필(46세, 옥천군, 귀농인) 기반 5개 정책 모두 매칭
- 응답 포맷: days_left (마감까지 일수), match_reason (매칭 이유)
- 권한 관리: Admin 전용 API 접근 제어 정상
- 에러 처리: 통일된 응답 포맷 (`{"error": "...", "code": "..."}`)
