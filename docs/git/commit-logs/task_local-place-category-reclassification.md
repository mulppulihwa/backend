# 사용처(LocalPlace) category 세분화 — 음식점/약국/건축자재 등 7개 신규 카테고리 추가

**날짜**: 2026-06-08
**커밋 로그**: [604b6d3](https://github.com/mulppulihwa/backend/commit/604b6d3)

## 작업 배경

프론트엔드에서 "옥천군 농어촌 기본소득 시범사업" 정책으로 사용처를 필터링하면
83곳 중 82곳이 모두 `category='생활'`로만 표시되어, 사용자가 "생활밖에 안 뜨는데
이게 맞냐"고 의문을 제기함. 확인 결과 해당 82곳은 `subsidy_tags`에
'향수OK카드'/'공익수당'이 태그되어 있어 정책 매칭 자체는 정상이었으나,
`category` 값이 모두 '생활'로 뭉뚱그려져 있어 사용자 입장에서 "어떤 가게들이
있는지" 한눈에 구분이 안 되는 문제가 있었음.

이에 사용자가 "category를 기존에 있던 것처럼 약국, 식품, 농기계 이런 식으로
분류해서 표시해 달라"고 명시적으로 요청 — `local_memo` 필드에 "업종: 일반음식점",
"업종: 의료기관/제약" 등 실제 업종 분류 데이터가 텍스트로 들어 있는 것을 발견하고,
이를 근거로 추측이 아닌 데이터 기반 재분류 매핑을 설계해 진행.

## AS-IS

- `LocalPlace.CATEGORIES`에 6개 선택지만 존재(`지원금사용처`/`농자재`/`농기계`/
  `농협`/`행정`/`생활`)
- 82곳의 사용처가 실제 업종과 무관하게 모두 `category='생활'`로 저장되어 있어
  프론트엔드 카테고리 필터/분류 UI에서 의미 있는 구분이 불가능

## 참고

- `category`(어떤 종류의 장소인지)와 `subsidy_tags`(어떤 지원금을 쓸 수 있는지)는
  `docs/schema.sql` 주석상 서로 다른 축으로 설계된 필드로, 재분류 전 "두 필드가
  orthogonal하니 재분류 대신 UI 문구만 바꾸자"는 대안도 검토했으나, 사용자가
  실제 업종 기준 재분류를 명시적으로 요청해 `local_memo`의 "업종:" 데이터를
  근거로 진행함
- `data/seed/local_places.json` 픽스처에는 pk=1(`category='행정'`) 1건만 존재해
  이번 일괄 업데이트 대상(82건)과 겹치지 않으므로 픽스처 동기화는 불필요
