# 귀향·귀농민 맞춤형 정책 안내 플랫폼 — 플랜

## 1. 문제 정의

### 발견된 핵심 문제
인터뷰를 통해 귀향민·귀농민이 겪는 주요 불편은 주민 간 갈등이나 이장 채널 문제가 아님을 확인.  
**실제 문제: 본인이 받을 수 있는 정책·지원을 몰라서 놓친다.**

- 중앙정부, 광역자치단체, 기초자치단체별로 정책이 분산되어 있음
- 정책 정보를 찾는 데 필요한 행정 리터러시(literacy) 격차 — 특히 디지털 접근이 어려운 노인층에서 심각
- "알고 보니 신청할 수 있었는데 기간이 지났다"는 후회 반복

### 솔루션 방향
**기본 페이지에서 간단한 정보 입력 → 본인이 받을 수 있는 정책을 바로 추천**하는 맞춤형 정책 안내 서비스.  
채팅 없이, 몇 가지 질문에 답하면 즉시 해당 정책 목록을 보여준다.

---

## 2. 타겟 사용자

### Primary Target
**노인 귀향·귀농민 (60세 이상)**
- 고향으로 돌아오거나 농촌으로 이주한 노년층
- 디지털 리터러시가 낮아 복잡한 정책 포털 탐색이 어려움
- 정책 정보 접근 격차가 가장 크고, 지원 필요도가 높은 집단
- 노인 복지 + 귀농귀촌 지원이 중첩되어 받을 수 있는 정책이 많지만 인지도 낮음

### Secondary Target

| 세그먼트 | 설명 |
|---|---|
| 귀농 준비자 | 도시에서 농촌으로 이주를 준비 중인 사람 |
| 귀향민 | 고향으로 돌아온 사람 (농업 외 직종 포함) |
| 귀농 초기 정착자 | 이주 후 1~3년 이내, 지원 탐색 중 |
| 대리 접근자 | 부모님을 위해 대신 정보를 찾는 자녀 세대 |
| 지역 공무원 / 지원 담당자 | 주민에게 정책을 안내해야 하는 중간 조력자 |

## 3. 핵심 기능

### 3-1. 맞춤 정책 추천 (MVP 핵심)
홈 페이지에서 몇 가지 질문에 답하면 해당 사용자가 받을 수 있는 정책을 즉시 보여준다.

**MVP 스코프 — 귀농·귀촌 특화 정책만**
- 중앙부처 귀농귀촌 지원 (농림축산식품부, 귀농귀촌종합센터)
- 충청북도 귀농귀촌 지원
- 옥천군 귀농귀촌 지원
- 국가 일반 복지(기초연금, 의료급여 등)는 **v2**로 분리

**화면 흐름**
```
비로그인 홈 → 카카오 로그인
  → 첫 방문: P1-B (/profile/setup, 5개 질문 입력)
  → 제출 후: 로그인 홈 (맞춤 정책 리스트 표시)
  → 재방문: 로그인 홈 바로 (저장된 프로필 자동 복원)
```
※ 폼 상세 및 UI 목업은 P1-B 참조

**매칭 방식**
- 입력값을 DB 조건(나이 범위, 지역 코드, 직종 태그 등)과 서버에서 직접 필터링
- AI 없이 규칙 기반 쿼리로 동작 (MVP는 flat 필터 쿼리)

**UX 원칙**
- 큰 글씨, 버튼 중심 인터페이스 (텍스트 입력 최소화)
- 질문 수 최대 5개로 제한 — 이탈 방지

**인증 정책**
- 홈 화면 맞춤 정책 추천: **로그인 필수**
- 비로그인 홈: 최신·마감임박 정책 3개 미리보기만 표시, 카카오 로그인 CTA 노출
- 로컬 백과사전·정책 상세·전체 정책 목록: 비로그인도 접근 가능
- 첫 로그인 시 프로필 입력 폼(5개 질문) → 저장 후 맞춤 홈으로 이동
- 재방문 시 저장된 프로필 자동 복원 (폼 재입력 불필요), 프로필 수정 가능

**정책 카드에 표시할 정보**
- 정책명 + 한줄 요약 (쉬운 말로)
- 지원 내용 (금액, 혜택 종류)
- 신청 자격 조건
- 신청 기간 / 마감일
- 신청 방법 및 담당 기관 링크
- "나에게 해당되는 이유" (매칭 근거)

### 3-2. 로컬 백과사전 (MVP 핵심)
귀농민이 마을 생활에서 실제로 필요한 장소 정보를 제공하는 큐레이션 디렉토리.  
구글 지도가 아니라 **"귀농 선배가 알려준 동네 가이드"** 포지셔닝.

**제공 카테고리**

| 카테고리 | 예시 |
|---|---|
| 지원금 사용처 | 옥천사랑상품권 가맹점, 온누리상품권 가맹점, 바우처 사용 가능 매장 |
| 농자재 | 농약사, 비료상, 종묘사 |
| 농기계 | 농기계 판매점, 농기계 수리 공업소 |
| 농협 | 농협 지점, 하나로마트 (다수 보조금 농협 구매 조건) |
| 행정 | 면사무소, 농업기술센터, 읍·면 주민센터 |
| 생활 | 의원·약국, 마트·슈퍼, 주유소·LPG, 택배 수령처 |

**각 장소에 담는 정보**
```
LocalPlace {
  이름, 카테고리, 주소, 전화번호
  lat, lng    // 카카오 로컬 API(주소→좌표 변환)로 자동 입력; 수동 보정 가능

  // 귀농 특화 메타
  지원금_태그       // ["옥천사랑상품권", "농기계구입지원", ...]
  영수증청구가능    // 이 가게 영수증으로 보조금 청구 가능 여부
  귀농인메모        // "청산면 유일한 농약사", "귀농인 처음와도 친절히 설명"
  가격정보          // UGC: "복숭아 봉투 한박스 OO원" 등 주민 공유
  마지막확인일
}
```

**관리자 장소 등록 플로우 (좌표 자동 변환)**
```
관리자가 주소 입력
  → [좌표 자동 입력] 버튼
  → 카카오 로컬 API GET /v2/local/search/address.json?query={주소}
  → lat, lng 자동 채움 (수동 수정 가능)
  → 저장
```

**두 가지 탐색 방식**

① **지도 뷰** — 카테고리 필터로 탐색
```
[지도 화면]
카테고리 탭: 전체 | 지원금 사용처 | 농기계 | 농자재 | 행정 | 생활

  📍 마커 탭 → 장소 카드 팝업
     이름 / 거리 / 전화하기 버튼 / 카카오맵 길찾기
```

② **챗봇** — 지원금 맥락으로 자연어 질문
```
사용자: "내가 최근에 농기계 구입 지원금 받았는데 어디서 쓸 수 있어?"
챗봇:   "농기계 구입 지원금은 아무 대리점에서나 구매 후
         30일 이내 면사무소에 영수증 제출하시면 돼요.
         근처 농기계 대리점 알려드릴게요:

         📍 OO농기계 (청산면, 2.3km)  📞 전화하기
         📍 OO기계 (옥천읍, 8km)      📞 전화하기"
```

**정책 추천 → 로컬 백과사전 연결 흐름**
```
정책 카드에서 [받았다] 체크
  ↓
지원금 유형 판별
  A. 가맹점 지정형 (지역화폐·바우처)
     → "아래 가맹점에서만 사용 가능합니다" + 가맹점 지도
  B. 자유구매 후 청구형 (농기계·농자재)
     → "어디서나 구매 가능, 영수증 제출 필요" + 근처 관련 가게 추천
         + [지금 영수증 사진 찍어두기] 버튼
```

## 4-2. 페이지 구조

### P1. 홈 페이지 `/`
**목적:** 비로그인 — 정책 미리보기 + 로그인 유도 / 로그인 — 맞춤 정책 홈

#### 비로그인 상태
```
┌─────────────────────────────────────┐
│  귀농·귀향하셨나요?                  │
│  받을 수 있는 지원금을 찾아드려요    │
│                                     │
│  ── 최신·마감임박 정책 미리보기 ──  │
│                                     │
│  ┌───────────────────────────────┐  │
│  │ 귀농 농업창업 지원금           │  │
│  │ 최대 300만원 · 마감 06.30     │  │
│  └───────────────────────────────┘  │
│  ┌───────────────────────────────┐  │
│  │ 옥천 청년 귀농 정착 지원      │  │
│  │ 최대 200만원 · 마감 07.15     │  │
│  └───────────────────────────────┘  │
│  ┌───────────────────────────────┐  │
│  │ 충북 귀촌 주거 지원           │  │
│  │ 최대 500만원 · 상시           │  │
│  └───────────────────────────────┘  │
│                                     │
│  내가 받을 수 있는 정책을 보려면    │
│  로그인이 필요해요                  │
│  [ 카카오로 시작하기 → ]            │
└─────────────────────────────────────┘
```
- 미리보기 카드 3개: 아래 쿼리로 선정
  ```sql
  -- 마감 임박(7일 이내) 정책 우선, 부족하면 최신 등록 순으로 채움
  (SELECT * FROM policies
    WHERE apply_end_date BETWEEN NOW() AND NOW() + INTERVAL '7 days'
    ORDER BY apply_end_date ASC LIMIT 3)
  UNION ALL
  (SELECT * FROM policies
    WHERE apply_end_date IS NULL OR apply_end_date > NOW() + INTERVAL '7 days'
    ORDER BY created_at DESC LIMIT 3)
  LIMIT 3;
  ```
- 카드 탭 → P3 정책 상세로 이동 가능 (비로그인도 상세 열람 허용)
- 큰 글씨, 버튼 중심

#### 로그인 + 프로필 있음 + 매칭 0개 (빈 상태)
```
┌─────────────────────────────────────┐

│  ── 전체 정책 최신순 ──             │
```

### P1-B. 프로필 입력 폼 `/profile/setup`
**목적:** 로그인 후 최초 1회 — 맞춤 매칭에 필요한 정보 수집

**진입:** 첫 로그인 시 자동 이동 / 홈 [내 정보 수정]

```
┌─────────────────────────────────────┐
│  내 정보를 입력하면                  │
│  맞춤 지원금을 찾아드려요            │
│                                     │
│  1. 어디 사세요?                    │
│     [충청북도 ▾]  [옥천군 ▾]        │
│                                     │
│  2. 나이가 어떻게 되세요?           │
│     [  65  ] 세                     │
│                                     │
│  3. 농사 지으세요?                  │
│     [ 예, 귀농했어요 ]  [ 아니요 ]  │
│     시작한 지: [ 1년 이내 ▾ ]       │
│                                     │
│  4. 가구 유형                       │
│     [ 혼자 ]  [ 부부 ]  [ 기타 ]    │
│                                     │
│  5. 소득 구간                       │
│     [ 기초수급 ]  [ 차상위 ]  [ 일반 ] │
│                                     │
│       [ 내 지원금 찾기 → ]          │
└─────────────────────────────────────┘
```
- 입력값은 사용자 프로필에 저장 (재방문 시 자동 복원)
- 제출 → 홈(P1 로그인 상태)으로 이동하며 맞춤 정책 표시
- 큰 글씨, 버튼 중심 (텍스트 입력 최소화)
- 질문 5개 고정

---

### 매칭 아키텍처
```
사용자 폼 입력 (지역, 나이, 직종, 가구, 소득)
    ↓
API Route
    ↓
① 행정구역 계층 조회 — 입력 지역 코드의 조상 코드 목록 추출
   (예: "46150" → ["46150", "46"])   // 순천시 → 전남 전체 포함
    ↓
② 정책 후보 1차 필터 (Supabase SQL)
    WHERE age BETWEEN min_age AND max_age
      AND region_codes && [조상코드목록]   // 상위 행정구역 정책도 매칭
      AND occupation_tags && [해당태그]
    ↓
③ 조건 트리 평가 — condition_tree JSONB를 서버에서 AND/OR/NOT 순회
   → 1차 필터 통과 정책 중 복합 조건 최종 검증
    ↓
매칭된 정책 목록 → 프론트엔드 표시
```

#### 행정구역 계층 쿼리 상세

행정구역은 **시·도 → 시·군·구 → 읍·면·동** 3단계 계층.  
사용자가 "전라남도 순천시"를 입력하면 "전라남도 전체 대상" 정책도 함께 매칭해야 한다.

```sql
-- 입력 지역 코드의 조상 코드 목록을 재귀 CTE로 조회
WITH RECURSIVE ancestors AS (
  SELECT code, parent_code FROM regions WHERE code = :user_region_code
  UNION ALL
  SELECT r.code, r.parent_code
  FROM regions r
  JOIN ancestors a ON r.code = a.parent_code
)
SELECT array_agg(code) AS ancestor_codes FROM ancestors;

-- 정책 매칭: 조상 코드 중 하나라도 region_codes 배열에 포함되면 매칭
SELECT * FROM policies
WHERE region_codes && :ancestor_codes   -- PostgreSQL 배열 겹침 연산자
  AND :user_age BETWEEN min_age AND max_age;
```

`regions` 테이블 구조:
```
regions {
  code        -- 행정구역 코드 ("46", "46150", "4615025600")
  name        -- 지역명 ("전라남도", "순천시", "해룡면")
  parent_code -- 상위 코드 (null이면 최상위)
  level       -- 1(시도) | 2(시군구) | 3(읍면동)
  full_name   -- "전라남도 순천시 해룡면"
}
```

#### 조건 트리 구조 상세

단순 태그 매칭으로 표현 못하는 복합 조건(예: "60세 이상이거나 기초수급자이면서 귀농 1년 이내")을  
`condition_tree` JSONB 필드에 AND/OR/NOT 트리로 저장한다.

```ts
// ConditionNode 타입 (서버에서 평가)
type ConditionNode =
  | { type: "AND" | "OR"; children: ConditionNode[] }
  | { type: "NOT"; child: ConditionNode }
  | { type: "LEAF"; field: string; op: "eq"|"in"|"between"|"gte"|"lte"; value: unknown }

// 예시: (나이 ≥ 60 OR 소득 = 기초수급자) AND 농업종사 = true
{
  "type": "AND",
  "children": [
    {
      "type": "OR",
      "children": [
        { "type": "LEAF", "field": "age",          "op": "gte",  "value": 60 },
        { "type": "LEAF", "field": "income_level", "op": "eq",   "value": "기초수급자" }
      ]
    },
    { "type": "LEAF", "field": "occupation_tags", "op": "in", "value": ["귀농","귀촌"] }
  ]
}
```

트리 평가는 API Route에서 재귀 함수로 수행 — DB 쿼리 밖에서 처리하므로  
1차 SQL 필터로 후보를 좁힌 뒤 트리 검증으로 최종 필터링한다.

**NextAuth 구현 주의:** `profile_completed`를 클라이언트에서 읽으려면 NextAuth `callbacks.jwt`와 `callbacks.session`에서 세션 토큰에 포함시켜야 함.
```ts
// nextauth 설정 예시
callbacks: {
  async jwt({ token, user }) {
    if (user) token.profile_completed = user.profile_completed;
    return token;
  },
  async session({ session, token }) {
    session.user.profile_completed = token.profile_completed;
    return session;
  }
}
```

- 정책 상세 페이지 (신청 안내, 담당 기관 링크) — 비로그인도 열람 가능
- 전체 정책 목록 (필터 탐색) — 비로그인도 접근 가능
- 로컬 백과사전 — 지도 뷰 + 장소 카드 (30~50곳 수동 등록) — 비로그인도 접근 가능
- 관리자 정책·장소 등록/수정 화면
- 귀농귀촌 특화 정책 20~30개 수동 입력 (충북 옥천 중심)
- 노인 접근성: 아래 최소 스펙 준수
  - **폰트 크기**: 본문 최소 18px, 제목 24px 이상
  - **버튼 높이**: 최소 52px (터치 타겟 44px 이상)
  - **줄 간격**: 1.6 이상
  - **색상 대비**: WCAG AA (4.5:1) 이상
  - **텍스트 입력 최소화**: 숫자/선택 버튼만, 자유 입력 지양
  - **한 화면에 정보 밀도 낮게**: 스크롤 없이 핵심 행동 1개
- **[CEO cherry-pick] D-7 마감 뱃지**: 정책 카드에 `apply_end_date < 7일` 이면 "마감 임박 D-N" 빨간 뱃지 표시

**포함 (v1.5)**

## 8. 배포 전 수동 검증 체크리스트

자동화 테스트 없이 배포하는 경우, 아래 항목을 직접 시나리오 실행으로 반드시 확인:

### condition_tree 매칭 검증 (최우선)
- [ ] `condition_tree = null`인 정책 → 태그 조건만으로 매칭 정상 동작
- [ ] `AND` 조건: 두 조건 모두 만족하는 사용자 → 매칭 / 하나만 만족 → 미매칭
- [ ] `OR` 조건: 하나라도 만족 → 매칭 / 둘 다 불만족 → 미매칭
- [ ] `NOT` 조건: 반전 정상 동작
- [ ] 중첩 트리 (AND 안에 OR): 예상 결과 수동 계산 후 비교

### 인증 플로우
- [ ] 비로그인 홈 → 최신 정책 3개 표시
- [ ] 카카오 로그인 최초 → `/profile/setup` 이동
- [ ] 프로필 저장 → 홈에 맞춤 정책 즉시 표시
- [ ] 로그아웃 → 재로그인 → 폼 없이 바로 맞춤 정책 표시
- [ ] `/admin` 비인증 접근 → 로그인 화면 또는 403

### 지역 계층 매칭
- [ ] 옥천군 사용자 → 옥천군 정책 + 충청북도 정책 모두 매칭
- [ ] 충청북도 사용자 → 충청북도 정책만 매칭 (옥천군 정책 미매칭)

### 로컬 백과사전
- [ ] 주소 입력 → 좌표 자동 변환 → 지도에 올바른 위치 표시
- [ ] 카테고리 탭 클릭 → 지도 마커 + 리스트 동시 필터링
- [ ] 장소 카드 탭 → 상세 페이지 이동
